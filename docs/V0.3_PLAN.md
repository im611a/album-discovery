# v0.3 数据架构执行计划

## 1. 计划定位

本文把 `docs/V0.3_DATA_AUDIT.md` 的真实仓库事实和 `docs/V0.3_DATA_CONTRACTS.md` 的目标契约转为文件级、可验证、可中止的 v0.3 执行顺序。

本计划的目标不是接入真实数据，而是建立真实数据接入前必须具备的领域边界、Repository、Query Service、持久化基础和后端一致性验证。

### 当前事实

- v0.2 最终基线：`4d96971`。
- annotated tag：`v0.2.0-prototype`，指向 `4d96971`。
- 当前页面读取完全虚构的本地 Mock 数据。
- 当前没有数据库、Prisma、正式 Provider 或真实同步。
- 0.15A、0.15B 只提供小规模实验事实，不是生产接口保证。
- RYM 只有离线导入边界，没有真实输入文件或实现。

### 本计划不自动授权

- 安装 Prisma、PostgreSQL 或任何依赖。
- 启动数据库服务或容器。
- 请求网易云或 RYM。
- 导入真实 RYM 文件。
- 修改、删除或迁移现有 Mock 数据。
- 部署、推送、合并 main 或进入 0.4。

每个阶段都必须获得独立用户指令。

## 3. 目标架构

```text
NetEase unknown JSON              RYM offline file
          │                              │
          ▼                              ▼
  source DTO parser                input adapter
          │                              │
          └──────────► normalizers ◄─────┘
                            │
                            ▼
                   Canonical Domain
                 Album / Artist / Track
                            │
            ┌───────────────┴────────────────┐
            ▼                                ▼
 Observation / Provenance              Repository writes
            │                                │
            └───────────────┬────────────────┘
                            ▼
                    Query Service
                            │
                            ▼
        AlbumSummary / AlbumDetail / Page<T>
                            │
                            ▼
                    Next.js pages / UI
```

实施完成后的硬边界：

- 页面不 import `src/data/*.mock.ts`。
- 页面不 import Provider DTO、Prisma Client 或数据库类型。
- Provider 不 import页面、React 组件或 Prisma模型。
- 内存和数据库后端实现相同 Query Service 契约。
- 真实来源只产生本地已发布快照，前台没有运行时上游请求。

### 7.5 查询语义

- 首页近期：发行日期降序，缺失日期置后，标题和 ID稳定 tie-break。
- 首页高分：调用方传入最小评分人数；不回填低于门槛的专辑。
- 随机：按 `SHA-256(seed + "\0" + albumId)` 字节升序，AlbumId 最终 tie-break。
- 发现：保持当前年代、类型、三类 taxonomy 和排序语义；PartialDate 使用固定 tuple。
- 搜索：六级匹配优先级、同级 PartialDate 降序、统一 TypeScript `zh-CN` comparator、ID tie-break；每张专辑一次。
- v0.3 合成数据先取得有界候选集、执行统一 TypeScript comparator，再切分 Page；真实规模数据库 collation/游标方案未验证前不得宣称生产可扩展。
- 新发行：ALL 为全部频道并集；频道+类型筛选；PartialDate 降序；保留 memberships 并投影 first/last discoveredAt。
- 详情：slug、别名、公司、评分、分类、曲目和外链空值语义不变。
- discover options 从当前 backend 可见投影的 TaxonomyLabel.key 构建；prototype 使用既有英文 URL 值，database 只读取已发布 stableKey。

### 9.5 核心 schema 范围

本阶段只建立：

- Album、AlbumSlug。
- Artist、ArtistAlias、AlbumArtistCredit。
- Track、TrackArtistCredit。
- AlbumAlias。
- ReleaseCompanyCredit。
- CoverAsset。
- ExternalIdentifier，作为外部来源身份与 canonical entity 关联的唯一权威。

SourceRecord、运行、发现、RatingSnapshot、MatchDecision 和 ManualOverride 留给 0.3E。核心 schema 不包含国家、地区、语言、国籍或市场频道 Album 字段。

AlbumAlias、ArtistAlias 和 ReleaseCompanyCredit 在 0.3D 只包含 canonical 基础字段：schema 不创建 `sourceRecordId` 列，不引用尚不存在的 SourceRecord，不创建占位表或字符串伪来源 ID。0.3D Prisma mapper 对三个领域对象一律输出 `sourceRecordId=null`。

### 9.6 约束

- 内部 UUID 主键。
- 当前和历史 slug 唯一。
- 外部标识联合唯一。
- ExternalIdentifier 恰好一个 canonical 外键非空且与 entityType 一致；后续 SourceRecord 只能引用 externalIdentifierId。
- 有序 credit、track position 和 alias position 唯一。
- AlbumAlias、ArtistAlias 和 ReleaseCompanyCredit 均无 `sourceRecordId` 列或悬空 provenance 外键。
- PartialDate precision 与列组合 check。
- duration 与 position 非负/正值 check。
- 删除策略明确；不能用默认 cascade 静默删除审计依赖。
- Prisma 无法表达的 check 写入 migration SQL，并有集成测试。

### 10.6 实现要求

- ExternalIdentifier 是唯一来源身份权威；SourceRecord 只通过 externalIdentifierId 关联，不保存 canonicalEntityId。
- NewReleaseDiscovery.albumId 与 RymRatingSnapshot.albumId 是 observation subject reference，不是第二套外部身份映射；任何 Observation / Snapshot 都不得另存可独立解析的 `source + entityType + externalId + canonicalEntityId`。
- 无法形成有效来源条目的解析/规范化失败在缺少稳定 externalId 时只写 RunEntryFailure，不创建虚假 ExternalIdentifier/SourceRecord；已形成的 RYM normalized row 不适用该失败路径。
- 无稳定 RYM ID 的行以 `(importRunId, sourceRowKey)` 定位，通过 sourceReferenceKey 进入 MatchDecision / ManualOverride；匹配前不得发布 RymRatingSnapshot，匹配后 albumId 只表示快照主体。
- AlbumAlias、ArtistAlias、ReleaseCompanyCredit 的 provenance migration 允许 `sourceRecordId=null`，索引该列并使用 `ON DELETE SET NULL`；删除 SourceRecord 不得 cascade 删除 canonical 内容。
- CatalogWriteService 通过 Prisma UnitOfWork 让 canonical、ExternalIdentifier、SourceRecord 和来源快照在单张专辑事务内。
- 相同 normalized hash 不复制观察快照。
- RatingSnapshot 原子保存 rating/count/三类 taxonomy。
- TaxonomyObservation 引用 termId、保存 sourceValueAtObservation，TaxonomyTerm 以 `(source, kind, stableKey)` 唯一。
- 新发行 membership 支持多频道和 first/last discovered。
- `reconcileAlbumTracks` 只按可靠 source track ID对齐；wouldDelete 不执行 destructive delete。
- 匹配决策与人工覆盖只追加，不覆盖历史。
- 数据库查询返回 read model，不返回 Prisma include 对象。
- 所有查询使用确定性 tie-break 和分页。

### 10.7 执行顺序

1. 先写从 0.3D schema 升级的 migration 与约束测试，创建 SourceRecord 后再增加三个 nullable provenance FK。
2. 实现 canonical/source mapper，SourceRecord mapper 不接受 canonicalEntityId。
3. 实现两个 Prisma Repository 和 Prisma UnitOfWork，并跑三套共享写入/事务契约。
4. 实现 Prisma Query Service，并跑共享查询契约。
5. 向隔离测试库加载无品牌 synthetic persistence contract；不得加载 v0.2 prototype fixture。
6. 对比两个 Repository 后端对同一 synthetic contract values 的输出。
7. 加后端工厂，但保持 memory 默认。
8. 完整 build，确认页面无外部请求。

### 10.8 测试要求

- CanonicalCatalogRepository、SourceObservationRepository 和 CatalogWriteService/UnitOfWork 共享契约在 PostgreSQL 通过。
- Query Service 共享契约在 PostgreSQL 通过。
- ExternalIdentifier 唯一权威、SourceRecord.externalIdentifierId 和无 ID RunEntryFailure 约束通过。
- Observation subject reference 可以引用 albumId，但 schema 不存在竞争性的 externalId/entityType/canonicalEntityId 映射组合。
- 无稳定 RYM ID 的 sourceRowKey 唯一范围、未匹配、人工匹配、拒绝和 supersede 行为通过；未匹配行不发布快照且不创建虚假 ExternalIdentifier。
- AlbumAlias、ArtistAlias、ReleaseCompanyCredit 可以关联 SourceRecord，`null` 仍合法；删除 SourceRecord 不 cascade 删除 alias/company credit，0.3D schema 可正常 migration 到 0.3E。

### 11.4 Runtime 规则

- 未配置时使用 memory，保证当前虚构原型可运行。
- database 只在显式环境配置和连接健康时启用。
- 前端 bundle 不包含 Prisma Client、数据库 URL 或 Provider parser。
- database 模式无数据时返回诚实空状态，不回退到 Mock 混合结果。
- database factory 禁止 import PrototypeFixtureState 或 prototype fixture adapter；生产数据库没有 prototype seed。
- 一个请求内只使用一个后端，不按查询逐条 fallback。

### 11.5 一致性矩阵

同一无品牌 synthetic persistence contract dataset 在两个 Repository/Query 后端必须逐项一致；该数据只存在于测试进程和隔离测试数据库，不是 v0.2 prototype fixture，也不是 production seed：

- 近期、高分和随机候选。
- 发现所有筛选与排序。
- 新发行 ALL 并集、多频道、类型和排序。
- 搜索六级优先级、去重、特殊字符和稳定排序。
- 分页 items、totalCount、nextCursor 行为。
- discover options 的 stableKey、sourceValue 和显示映射。
- PartialDate 固定 tuple、SHA-256 seeded random、统一 TypeScript `zh-CN` comparator。

- `origin="PUBLISHED_SOURCE_DATA"`。

- 自动进入下一阶段、推送、合并 main、创建 tag 或部署。

## 14. 全局风险与决策点

| 决策点 | 必须取得的证据 | 未取得时的动作 |
| --- | --- | --- |
| NetEase type 映射 | 更多获准样本中的 raw type/subType | 保留 raw，canonical UNKNOWN |
| 日期精度 | 来源真实响应是否存在不完整日期 | 使用 PartialDate，不补造 |
| track reconciliation | 缺 ID、下架、重排的真实样本 | 不执行 destructive replace |
| RYM 输入 adapter | 用户提供的获准离线文件样本 | 只保留 RymNormalizedRow 契约 |
| PostgreSQL 环境 | 本地/CI/目标部署方法 | 停止 0.3D |
| Prisma 可用性 | 实施时官方兼容性与 schema 验证 | 比较备选，不安装双 ORM |
| 全文搜索 | PostgreSQL 与中文搜索实测 | v0.3 保持当前规范化 substring 语义 |
| 封面缓存 | URL 稳定性、许可和缓存策略 | 只存 source URL/status，不批量下载 |
| 发布合规门 | 数据来源说明和项目政策 | 导入可 dry-run，不发布快照 |
