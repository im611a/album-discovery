## 0.1 已确认与未确认

已确认事实仅来自公开仓库只读研究：存在第三方 Node.js 实现，代码中包含专辑

证据。

## 0.15 要回答的问题

1. 不登录、不提供个人 Cookie 时，哪些目录接口类别可稳定返回？
2. 新碟、搜索、艺术家专辑、专辑详情和曲目结果能否组成可追溯的最小目录？
3. 专辑 ID、标题、艺术家、发行日期、封面、曲序和官方专辑链接是否完整？
4. 分页、重复版本、下架、区域差异和缺失字段如何表现？
5. 单并发低频访问下的延迟、错误率、429/风控信号和响应结构变化如何？
6. 访问方式、缓存、封面使用和批量处理是否满足适用条款与合规要求？

## 隔离实验设计（收到授权后才执行）

- 在独立的 0.15 变更中创建最小实验；当前不创建
  `experiments/netease-catalog-spike`。
- 只使用合成搜索词和少量公开专辑 ID，不使用真实用户行为数据。
- 从无账号、无个人 Cookie 路径开始；不测试登录、验证码、播放或解锁接口。
- 单并发、固定间隔、有限分页；建议首轮总请求不超过 50 次。
- 遇到 401、403、429、验证码、风控提示或异常响应率立即停止。
- 只保存脱敏响应样例、结构摘要、时间、状态码和版本信息，不保存凭据。

## 验证矩阵

| 接口类别 | 最小样本 | 需要记录 | 通过信号 |
| --- | --- | --- | --- |
| 专辑搜索 | 多种中英文标题 | 分页、ID、版本歧义 | 可匿名、结构稳定、能定位专辑 |
| 新碟/近期发行 | 少量分页 | 时间范围、重复、区域参数 | 可解释的候选集合和发行字段 |
| 艺术家专辑 | 少量艺术家 | 分页、合作/合辑行为 | 可补覆盖且不会无限扩张 |
| 专辑详情 | 已知与边界 ID | 标题、艺术家、日期、封面 | 核心字段完整且错误可分类 |
| 曲目详情 | 单碟与多碟样本 | 曲序、碟号、艺术家 | 能稳定形成展示用曲目表 |
| 官方专辑链接 | 上述专辑 | URL 模板与跳转目标 | 指向网易云专辑页且无需本站播放 |

“通过信号”是未来判据，不代表当前已经通过。

## 证据要求

每次实验必须记录：

- 日期、代码版本、运行环境和网络区域；
- 请求类别、参数类别、节奏和总量；
- 状态码/业务码分布、延迟、重试和停止原因；
- 脱敏样例的字段覆盖率与结构校验结果；
- 是否使用匿名状态，以及是否观察到 Cookie/登录要求；
- 条款与许可证复核结果。

禁止只用“浏览器里能打开”或第三方项目声称支持作为通过证据。

## 决策门

- **通过**：核心目录在无个人账号路径下满足字段、稳定性、节奏和合规要求。
- **有条件通过**：可行但需要代理服务、短期令牌或高维护逆向；必须再次审批
  运维与合规成本，不能自动进入实现。
- **不通过**：依赖个人账号/验证码、持续风控、不可接受条款、字段不足或稳定性
  无法满足。此时回到产品和数据策略决策，不绕过限制。
