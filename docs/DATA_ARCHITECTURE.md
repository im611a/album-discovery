# 数据架构

本文定义逻辑数据模型、字段权威和数据流。阶段 0.1 不选择 ORM、不创建
数据库，也不代表任何真实数据已获取。

## 字段权威矩阵

| 数据 | 正式来源 | 说明 |
| --- | --- | --- |
| 专辑目录与网易云专辑 ID | 网易云音乐 | 作为目录主键来源和去重基础 |
| 专辑名、艺术家、发行日期 | 网易云音乐 | 保留上游原始值与规范化值 |
| 封面与曲目 | 网易云音乐 | 封面只保存可追溯引用；曲目保留顺序 |
| 唯一收听入口 | 网易云音乐 | 只链接官方专辑页，不提供站内播放 |
| 评分与评分人数 | RYM | 同一快照一起导入，缺失不置零 |
| Primary Genres | RYM | 有序多值字段 |
| Secondary Genres | RYM | 与 Primary Genres 分开保存 |
| Descriptors | RYM | 描述词，不作为流派层级 |

MusicBrainz、Cover Art Archive、ListenBrainz 和 Last.fm 不进入正式字段来源
链。它们既不参与第一版补全，也不作为回退源。

## 逻辑实体

### Album

- 站内稳定 ID；
- 唯一网易云专辑 ID；
- 标题、发行信息、封面引用、网易云收听链接；
- 首次收录时间、最后成功同步时间、发布状态。

### Artist 与 Track

- Artist 保存网易云艺术家 ID 和展示名；专辑与艺术家为多对多关系并保留顺序。
- Track 保存网易云曲目 ID、碟号、曲序、标题和艺术家关系。
- Track 只用于专辑曲目展示，不包含音频 URL。

### RymEnrichment

- 关联站内专辑 ID；
- 评分、评分人数、快照日期；
- Primary Genres、Secondary Genres、Descriptors 三个独立有序集合；
- 原始记录引用、导入批次和匹配置信度。

### Provenance 与 Batch

- SourceRecord 保存来源、上游标识、获取/导入时间和内容校验和。
- IngestionBatch 保存任务类型、版本、数量、失败分类与停止原因。
- MatchDecision 保存候选、匹配规则、置信度和人工复核状态。
- PublishedSnapshot 表示前台当前可读取的、通过质量检查的数据版本。

这些是逻辑职责，不规定数据库表的最终拆分方式。

## 数据流

```text
获准的上游或离线文件
        ↓
原始记录 / 批次证据
        ↓
规范化与字段校验
        ↓
网易云目录记录 ← 专辑匹配 → RYM 丰富记录
        ↓
质量检查与可追溯性检查
        ↓
不可变发布快照
        ↓
Next.js 前台只读消费
```

采集失败不能直接破坏当前发布快照；重新运行必须幂等，并能从批次记录判断
哪些数据发生变化。

## 专辑匹配原则

1. 网易云专辑 ID 只标识网易云目录，不尝试把 RYM ID 写成同一命名空间。
2. RYM 候选匹配使用规范化标题、主要艺术家、发行年份和版本信息。
3. 精确且无冲突的候选可高置信度接受；多候选、重发版、豪华版、同名专辑
   进入人工复核。
4. 任何匹配都保留规则版本和证据，不以模糊标题覆盖既有结果。

具体导入策略见 `RYM_IMPORT_STRATEGY.md`。

## 发布读模型

前台所需读模型只暴露：专辑摘要、四个首页集合、专辑详情和数据更新时间。
读模型不暴露上游 Cookie、原始响应、内部失败信息或音频地址，也不在请求时
回源网易云或 RYM。

## 当前未决事项

- 持久化技术与物理表结构留到后续阶段决定；当前不安装 Prisma、不接入
  PostgreSQL。
- 覆盖率、刷新周期、RYM 匹配阈值和高分模块的最低评分人数需要真实数据
  分布后再定。
- 网易云接口可行性必须通过 0.15 的独立验证，当前没有实测结论。
