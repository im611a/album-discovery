# v0.3 数据契约

## 1. 文档定位

本文定义 v0.3 的数据层边界、领域语义、只读查询契约、来源追踪和持久化约束。它是后续实现的设计输入，不代表当前仓库已经存在这些 TypeScript 文件、数据库表、Provider 或真实数据。

本文中的接口名和候选文件名属于文档级契约。当前没有创建生产 TypeScript 或 Prisma Schema；实施阶段必须重新对照真实基线，发现命名冲突时停止并更新计划，不能机械创建重复类型。

契约目标：

- 保持 v0.2 已验收的页面行为。
- 让页面不再依赖 `src/data/*.mock.ts`。
- 让网易云和 RYM 各自拥有明确、不可混淆的来源边界。
- 让内存实现与数据库实现共享同一查询语义。
- 支持来源变化、重复导入、匹配冲突和人工覆盖的审计。

## 2. 四层数据边界

```text
来源 DTO
  └─ 校验 / 规范化 / 映射
       └─ Canonical Domain（稳定身份与作品结构）
            ├─ Observation / Provenance（来源快照、发现、评分、匹配）
            └─ Read Model / Query Service（页面专用只读结果）
```

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| 来源 DTO | 原样承接某次来源响应或离线行的可识别字段 | 页面展示、跨来源合并、业务默认值 |
| Canonical Domain | 内部身份、专辑、艺术家、曲目、发行结构 | 保存某次抓取状态或把缺失字段猜完整 |
| Observation / Provenance | 来源记录、快照、频道发现、RYM 评分分类、匹配与覆盖 | 充当页面直接 API |
| Read Model / Query | 分页、筛选、搜索、稳定排序和页面字段 | 暴露 ORM 对象或来源原始响应 |

页面、组件和客户端状态只能依赖 Read Model。Provider 不得 import React、页面组件或 Prisma 模型。

## 3. 标识符契约

### 3.1 内部 ID

正式领域实体使用 Provider 无关的 opaque string ID。持久化实现推荐 UUID v4；TypeScript 不让调用方依赖其格式。

```ts
type AlbumId = string;
type ArtistId = string;
type TrackId = string;
type CoverAssetId = string;
type ExternalIdentifierId = string;
type SourceRecordId = string;
type ImportRunId = string;
type SyncRunId = string;
```

规则：

- 内部 ID 永不等于网易云专辑 ID、网易云艺术家 ID、RYM URL 或 Mock ID。
- 外部 ID 变化不导致内部 ID 变化。
- API 和页面把 ID 当作不可解析字符串。
- 当前 `mock-001` 一类 ID 只属于测试 fixture。

### 3.2 外部标识

```ts
type SourceSystem = "NETEASE" | "RYM";
type ExternalEntityType = "ALBUM" | "ARTIST" | "TRACK";

interface ExternalIdentifier {
  id: ExternalIdentifierId;
  source: SourceSystem;
  entityType: ExternalEntityType;
  externalId: string;
  albumId: AlbumId | null;
  artistId: ArtistId | null;
  trackId: TrackId | null;
  firstObservedAt: string;
  lastObservedAt: string;
}
```

持久化约束：

- ExternalIdentifier 是稳定外部实体身份与 canonical entity 关联的唯一权威。SourceRecord 不得保存第二套身份映射；Observation / Snapshot 可以引用其观察的 canonical 主体，但该主体引用不构成外部身份映射。
- `(source, entityType, externalId)` 唯一。
- 三个 canonical 外键恰好一个非空，并与 `entityType` 一致。
- 外部数字 ID 以十进制字符串保存，避免 JavaScript 安全整数和跨 Provider 类型差异。
- RYM 若提供稳定 opaque ID，则以该 ID作为 externalId；若只有规范化 URL，则以版本化 canonical URL/path 作为 externalId，并在 SourceRecord 保留原始引用。没有稳定引用时不伪造 RYM ID。
- 没有稳定 RYM 标识时，以 `(importRunId, sourceRowKey)` 定位导入行，并以 `sourceReferenceKey` 审计匹配；匹配完成前不发布 RymRatingSnapshot。存在稳定 ID 或规范化 URL 时，也只有匹配成功后才创建 ExternalIdentifier。
- SourceRecord 只保存 `externalIdentifierId`，不保存 `entityType`、`externalId` 或 `canonicalEntityId`；查询该来源记录对应的 canonical entity 时只能沿 ExternalIdentifier 解析。
- Observation / Snapshot 不得同时保存一套可独立解析的 `source + entityType + externalId + canonicalEntityId`。`NewReleaseDiscovery.albumId`、`RymRatingSnapshot.albumId` 一类字段只是 observation subject reference。

### 3.3 Slug

```ts
interface AlbumSlug {
  albumId: AlbumId;
  slug: string;
  isCurrent: boolean;
  createdAt: string;
  retiredAt: string | null;
}
```

规则：

- slug 是 URL 标识，不是主键。
- 当前 slug 全局唯一；历史 slug 也保留唯一映射，用于稳定重定向。
- 初次生成基于规范化标题；冲突时添加由内部 ID 派生的短、确定性后缀。
- 不使用网易云 ID 作为默认 slug 后缀，避免把页面 URL 绑定到 Provider。
- 标题变化不自动破坏旧 URL；新 slug 生效后旧 slug 进入历史记录。

## 4. 日期与时间契约

### 4.1 部分发行日期

```ts
type DatePrecision = "DAY" | "MONTH" | "YEAR" | "UNKNOWN";

interface PartialDate {
  year: number | null;
  month: number | null;
  day: number | null;
  precision: DatePrecision;
}
```

不变量：

- `DAY`：year、month、day 全部存在且组成合法日期。
- `MONTH`：year、month 存在，day 为 null。
- `YEAR`：year 存在，month、day 为 null。
- `UNKNOWN`：year、month、day 全为 null。
- 不把只有年份的来源值补成 1 月 1 日。
- 排序使用明确的 sort key；缺失日期始终放在有日期记录之后，再按标题和内部 ID稳定排序。
- PostgreSQL 使用 `releaseYear`、`releaseMonth`、`releaseDay` 三个 nullable 整数列和 `releaseDatePrecision` 枚举/check，不用单一 `date`、`datetime` 或显示字符串伪装未知精度。

### 4.2 事件时间

所有事件时间使用 UTC ISO 8601 字符串进入 TypeScript 边界，数据库保存 timezone-aware timestamp。

| 字段 | 含义 |
| --- | --- |
| `fetchedAt` | 一次 HTTP 响应完成的时间 |
| `observedAt` | 来源数据代表的观察时点；来源未提供时可等于 fetchedAt，但必须记录推导 |
| `importedAt` | 离线文件进入本地导入流程的时间 |
| `discoveredAt` | 单次来源列表观察中发现专辑的事件时间；membership 聚合为 firstDiscoveredAt / lastDiscoveredAt |
| `createdAt` | 本地记录首次持久化时间 |
| `updatedAt` | 本地记录最近修改时间 |

这些字段不能互换。发行日期不是事件时间。

## 5. Canonical Domain

### 5.1 Album

```ts
type AlbumType =
  | "ALBUM"
  | "EP"
  | "MIXTAPE"
  | "SOUNDTRACK"
  | "SINGLE"
  | "OTHER"
  | "UNKNOWN";

interface Album {
  id: AlbumId;
  title: string;
  releaseDate: PartialDate;
  albumType: AlbumType;
  createdAt: string;
  updatedAt: string;
}
```

规则：

- `title` 是当前规范化主标题，不能为空白。
- 原始标题和别名不丢失，进入 SourceRecord 或 AlbumAlias。
- `releaseYear` 不作为独立权威字段；页面从 `releaseDate.year` 读取。
- `albumType` 是内部受控枚举；来源原始 `type`、`subType` 和映射版本保留在来源层。
- 国家、地区、语言、国籍不属于 v0.3 核心 Album。
- 市场频道不属于 Album。

### 5.2 AlbumAlias

```ts
type AlbumAliasKind = "ALIAS" | "TRANSLATED_TITLE" | "SOURCE_VARIANT";

interface AlbumAlias {
  id: string;
  albumId: AlbumId;
  value: string;
  kind: AlbumAliasKind;
  position: number;
  sourceRecordId: SourceRecordId | null;
}
```

同一专辑的规范化重复别名不得重复展示，但来源记录仍保留原始数组。

标题规则：

- Album.title 是当前主标题，不强制区分中文标题或英文标题。
- 原始主标题保留在 SourceRecord；来源明确声明的译名进入 `TRANSLATED_TITLE`。
- 不假设每张专辑同时具有中文和英文标题，不创建空的 `chineseTitle` / `englishTitle` 占位字段。
- 搜索规范化文本是可重建索引或查询投影，不是显示标题；至少执行 Unicode 规范化、trim 和大小写归一，规则版本必须记录。
- 页面始终展示原始可读标题/别名，不展示搜索规范化文本。

### 5.3 Artist 与 credit

```ts
interface Artist {
  id: ArtistId;
  name: string;
  createdAt: string;
  updatedAt: string;
}

interface ArtistAlias {
  id: string;
  artistId: ArtistId;
  value: string;
  position: number;
  sourceRecordId: SourceRecordId | null;
}

interface AlbumArtistCredit {
  albumId: AlbumId;
  artistId: ArtistId;
  position: number;
  creditedName: string | null;
}

interface TrackArtistCredit {
  trackId: TrackId;
  artistId: ArtistId;
  position: number;
  creditedName: string | null;
}
```

规则：

- 专辑艺术家和曲目艺术家分别有序。
- `creditedName` 保留某次发行上的显示写法；为空时使用 Artist.name。
- 多艺术家专辑不创建虚构“Various Artists”实体，除非来源本身明确提供并经过映射。
- 艺术家国家、地区、语言、国籍不在当前模型中。
- 网易云 artistId 通过 ExternalIdentifier 关联，不作为 Artist.id。
- 未匹配来源艺术家先保存在 SourceRecord 的有序 artist reference 中；没有外部 ID或同名冲突时不强制创建 canonical Artist。
- 匹配成功后建立 credit；失败、候选和人工覆盖进入 MatchDecision / ManualOverride。

### 5.4 Track

```ts
interface Track {
  id: TrackId;
  albumId: AlbumId;
  title: string;
  position: number;
  discNumber: number | null;
  trackNumber: number | null;
  durationMs: number | null;
  createdAt: string;
  updatedAt: string;
}
```

规则：

- `position` 是本地稳定展示顺序，从 1 开始，在专辑内唯一。
- `discNumber` 与 `trackNumber` 保留来源值，不按数组下标猜测。
- 来源出现非连续曲序时保留非连续值。
- `durationMs` 必须为非负整数或 null。
- 曲目外部 ID通过 ExternalIdentifier 关联。
- ISRC 不在 v0.3 必填契约；字段位置预留为可空标准录音标识，只有可靠来源出现后才加入 schema。
- 隐藏曲目没有独立可靠字段时不猜测；它仍按来源位置作为普通 Track，来源原始标题和序号保留在 SourceRecord。
- 缺失曲序时 `trackNumber=null`，但 `position` 仍按有效来源数组顺序生成并记录推导；不得伪造来源曲序。

### 5.5 发行公司 credit

```ts
interface ReleaseCompanyCredit {
  id: string;
  albumId: AlbumId;
  displayName: string;
  position: number;
  sourceRecordId: SourceRecordId | null;
}
```

当前证据只证明网易云样本有一个可空公司字符串。v0.3 先保存有序显示 credit，不提前建立全局 Company 主数据实体。空字符串规范化为无记录，页面隐藏该行。

#### 5.5.1 来源证据的领域契约与数据库阶段

领域契约从 0.3A 起允许 `AlbumAlias`、`ArtistAlias` 和 `ReleaseCompanyCredit` 包含 `sourceRecordId: SourceRecordId | null`。该字段只表示可选来源证据，不参与 canonical 内容的身份或生命周期。

0.3D 只创建这三张表的 canonical 基础字段：

- 不创建 `sourceRecordId` 数据库列或指向 SourceRecord 的外键；
- 不创建虚构的 SourceRecord 占位表，也不使用字符串形式的伪来源 ID；
- 0.3D 的 Prisma mapper 必须把三个领域对象的 `sourceRecordId` 返回为 `null`；
- 0.3D schema 不得引用尚不存在的 SourceRecord。

0.3E 创建 SourceRecord 后，必须通过新的 migration 为三张表分别增加 nullable `sourceRecordId`、索引和指向 SourceRecord 的外键。`onDelete` 明确使用 `SET NULL`，不得用 cascade 静默删除 alias 或 company credit；`null` 仍是合法状态。

### 5.6 封面资产

```ts
type CoverAssetStatus = "REMOTE_ONLY" | "CACHED" | "UNAVAILABLE" | "FAILED";

interface CoverAsset {
  id: CoverAssetId;
  albumId: AlbumId;
  source: SourceSystem;
  sourceUrl: string | null;
  cachedPath: string | null;
  width: number | null;
  height: number | null;
  variant: string | null;
  status: CoverAssetStatus;
  fetchedAt: string | null;
}
```

规则：

- 页面不直接依赖 Provider DTO 的封面字段。
- 远程 URL 与本地缓存路径分开。
- v0.2 CSS MockCover 只进入测试 read-model fixture，不迁移为生产 CoverAsset。
- 缺少封面时由读模型返回显式 placeholder 状态，不伪造来源 URL。

### 5.7 Genre、Descriptor 与专辑投影

```ts
type TaxonomyKind = "PRIMARY_GENRE" | "SECONDARY_GENRE" | "DESCRIPTOR";

interface TaxonomyTerm {
  id: string;
  source: "RYM";
  kind: TaxonomyKind;
  sourceValue: string;
  stableKey: string;
}

interface TaxonomyLabelTranslation {
  termId: string;
  locale: string;
  label: string;
}
```

决定：

- Genre 与 Descriptor 需要独立稳定 term；`kind` 保证 Primary、Secondary、Descriptor 不混用。
- `sourceValue` 保存 RYM 离线输入显示名，`stableKey` 是站内稳定键，不用中文名作身份。
- TaxonomyTerm 的数据库唯一键至少为 `(source, kind, stableKey)`。
- 当前 v0.2 英文分类 URL 值作为第一版 stableKey，避免 0.3 数据边界迁移改变既有链接。
- 中文显示映射属于 `TaxonomyLabelTranslation` 或当前 `getDisplayLabel` 投影；没有翻译时回退 sourceValue。
- 来源顺序保存在 RatingSnapshot 的 observation position。
- 不建立“永恒有效”的 AlbumGenre / AlbumDescriptor 作为权威关系；它们只作为最近已发布 RatingSnapshot 的可重建当前投影。
- 数据库若为查询性能物化 AlbumGenre / AlbumDescriptor，必须保存 snapshotId，并能从快照完全重建，不能脱离来源快照单独编辑。

## 6. 来源 DTO 契约

### 6.1 字段状态

来源 DTO 解析器必须区分字段状态：

```ts
type SourceField<T> =
  | { state: "PRESENT"; value: T }
  | { state: "EXPLICIT_NULL" }
  | { state: "ABSENT" }
  | { state: "INVALID"; rawValue: unknown; reason: string };
```

DTO 解析阶段不把 absent、null、invalid 合并。进入 canonical 后：

- 可空标量使用 `null`。
- 没有成员的集合使用 `[]`。
- `undefined` 只表示 DTO 属性未提供，不出现在领域对象或读模型 JSON 中。
- 不使用 `"Unknown"`、`"N/A"`、`0` 或虚构日期代替缺失值。

TypeScript 与数据库映射：

| 语义 | TypeScript DTO | Canonical / Read Model | PostgreSQL |
| --- | --- | --- | --- |
| 字段未提供 | `SourceField.state="ABSENT"` | 可空标量 `null`，不生成集合成员 | nullable column 或无关联行；SourceSnapshot 保留 ABSENT issue |
| 来源显式空 | `EXPLICIT_NULL` | 按字段规则转 `null` / `[]` | nullable column / 无关联行；snapshot 保留显式空状态 |
| 非法值 | `INVALID` + rawValue + reason | 不进入有效 canonical 字段 | snapshot validation issue / 可控 JSON 元数据，不写假默认值 |
| 空集合 | `PRESENT` + `[]` | `readonly []` | 关联表 0 行 |
| 未支持枚举 | `PRESENT` raw string | canonical `UNKNOWN` | 枚举 UNKNOWN + SourceRecord raw 值和 mappingVersion |
| 未找到页面实体 | 不适用 | Query 返回 `null` | 查询 0 行，不抛底层 SQL 文本 |

### 6.2 NetEase DTO

0.15A 只证明规范化器实际访问过若干路径，没有保存完整原始响应。v0.3 的 DTO 必须以宽容、可校验结构表示：

```ts
interface NeteaseAlbumSourceDto {
  externalAlbumId: SourceField<string>;
  title: SourceField<string>;
  aliases: SourceField<string[]>;
  artists: SourceField<NeteaseArtistSourceDto[]>;
  releaseTimestampMs: SourceField<number>;
  rawAlbumType: SourceField<string>;
  rawSubType: SourceField<string>;
  company: SourceField<string>;
  coverUrl: SourceField<string>;
  reportedTrackCount: SourceField<number>;
  tracks: SourceField<NeteaseTrackSourceDto[]>;
}

interface NeteaseArtistSourceDto {
  externalArtistId: SourceField<string>;
  name: SourceField<string>;
}

interface NeteaseTrackSourceDto {
  externalTrackId: SourceField<string>;
  title: SourceField<string>;
  trackNumber: SourceField<number>;
  discNumber: SourceField<number>;
  artists: SourceField<NeteaseArtistSourceDto[]>;
  durationMs: SourceField<number>;
  sourcePosition: number;
}

interface NeteaseNewReleaseRecordDto {
  requestedMarketChannel: NeteaseMarketChannel;
  sourceListEndpoint: string;
  sourcePosition: number;
  album: NeteaseAlbumSourceDto;
  fetchedAt: string;
}
```

DTO 规则：

- 网络 JSON 首先按 `unknown` 接收，再通过显式解析器产生 DTO。
- 响应中的备用路径在解析器内集中处理，不能散落在领域层。
- 每个映射结果记录 `parserVersion` 与 `mappingVersion`。
- 原始类型值保留；内部 AlbumType 映射无法确认时为 UNKNOWN，而不是猜测。
- `reportedTrackCount` 与实际解析曲目数分别保存，差异进入验证报告。
- 不定义 `country`、`region` 或 `language`，除非后续独立实验确认稳定字段并更新产品决策。

### 6.3 RYM 离线输入 DTO

真实离线文件结构尚未确认，因此 v0.3 只冻结规范化输出，不冻结 CSV/JSON 列名：

```ts
interface RymImportRowDto {
  rowNumber: number;
  rawColumns: Readonly<Record<string, unknown>>;
}

interface RymNormalizedRow {
  sourceRowKey: string;
  sourceAlbumReference: string | null;
  title: string;
  aliases: string[];
  artists: string[];
  releaseDate: PartialDate;
  rating: number | null;
  ratingCount: number | null;
  primaryGenres: string[];
  secondaryGenres: string[];
  descriptors: string[];
  observedAt: string | null;
}
```

规则：

- 输入适配器在获得获准的真实样本后单独实现。
- `RymImportRowDto` 只保存离线文件一行的近原始列；列名映射属于版本化 input adapter，不写进 canonical 类型。
- 评分和评分人数来自同一行或同一快照。
- 三类分类保持输入顺序和分类边界。
- 导入器记录文件校验和、来源说明、导入时间和规范化器版本。
- 导入器不获取 RYM 数据，不登录、不抓取、不绕过访问限制，也不自行证明用户文件授权。

## 7. 来源、观察与审计模型

ExternalIdentifier 负责稳定外部实体身份到 canonical entity 的唯一映射。以下 observation / snapshot 的 `albumId` 只表示“这条观察针对哪张 canonical 专辑”，不与 ExternalIdentifier 竞争来源身份权威；它们不得同时携带可独立解析的 `source + entityType + externalId + canonicalEntityId` 映射。

### 7.1 运行记录

```ts
interface SyncRun {
  id: SyncRunId;
  source: "NETEASE";
  operation: string;
  requestedScope: string;
  startedAt: string;
  completedAt: string | null;
  status: "RUNNING" | "SUCCEEDED" | "PARTIAL" | "FAILED";
  sourceVersion: string | null;
  parserVersion: string;
  normalizerVersion: string;
  requestCount: number;
  successCount: number;
  failureCount: number;
  errorSummary: string | null;
}

interface ImportRun {
  id: ImportRunId;
  source: "RYM";
  operation: "VALIDATE" | "DRY_RUN" | "IMPORT";
  requestedScope: string;
  sourceDescription: string;
  fileName: string;
  fileChecksum: string;
  startedAt: string;
  completedAt: string | null;
  importedAt: string;
  sourceVersion: string | null;
  normalizerVersion: string;
  status: "VALIDATED" | "DRY_RUN" | "IMPORTED" | "PARTIAL" | "FAILED";
  rowCount: number;
  successCount: number;
  failureCount: number;
  errorSummary: string | null;
}
```

运行记录不得保存 Cookie、Token、Authorization、Set-Cookie、账号信息、浏览器数据或完整请求头。

### 7.2 SourceRecord 与 FetchSnapshot

```ts
interface SourceRecord {
  id: SourceRecordId;
  externalIdentifierId: ExternalIdentifierId;
  endpoint: string | null;
  context: Readonly<Record<string, string>>;
  contextHash: string;
  normalizedPayloadHash: string;
  rawPayloadReference: string | null;
  parserVersion: string;
  mappingVersion: string;
  firstObservedAt: string;
  lastObservedAt: string;
  normalizationStatus: "VALID" | "PARTIAL" | "INVALID";
  lastError: string | null;
}

interface SourceFetchSnapshot {
  id: string;
  sourceRecordId: SourceRecordId;
  syncRunId: SyncRunId | null;
  importRunId: ImportRunId | null;
  fetchedAt: string | null;
  importedAt: string | null;
  observedAt: string;
  normalizedPayloadHash: string;
  validationStatus: "VALID" | "PARTIAL" | "INVALID";
  validationIssues: readonly string[];
}

interface RunEntryFailure {
  id: string;
  syncRunId: SyncRunId | null;
  importRunId: ImportRunId | null;
  sourcePosition: number | null;
  payloadHash: string | null;
  rawPayloadReference: string | null;
  errorCode: string;
  errorSummary: string;
  recordedAt: string;
}
```

`rawPayloadReference` 是受控存储引用，不要求把原始响应放进关系数据库，更不得提交敏感响应到 Git。0.15 实验没有保存原始响应，v0.3 不能伪造其引用。

不单独创建只服务 Album 的 `AlbumSourceRecord`：通用 SourceRecord 通过 `externalIdentifierId` 关联 ExternalIdentifier，并由后者唯一解析 Album、Artist 或 Track。SourceRecord 不保存 `canonicalEntityId`、`entityType` 或另一份 `externalId`，避免形成可能冲突的第二套身份权威。若 0.4 证明三类来源字段或保留策略无法共享，必须先用真实样本和 migration 影响说明再拆表。

失败与部分成功规则：

- 来源请求失败记录在 SyncRun 的计数、errorSummary 和请求级非敏感日志中；没有 payload 时不创建虚假 SourceRecord。
- 能识别稳定 externalId 的单条解析失败可以产生关联既有 SourceRecord 的 `INVALID` snapshot；不能识别稳定 externalId 时，不创建虚假 ExternalIdentifier、SourceRecord 或 SourceFetchSnapshot，只创建 RunEntryFailure。
- RunEntryFailure 必须保留非敏感错误、source position、payload hash 或受控引用；`syncRunId` 与 `importRunId` 恰好一个非空。
- RunEntryFailure 处理无法形成有效来源条目的解析/规范化失败，不替代已形成 RymNormalizedRow 的匹配流程；后者即使没有稳定外部 ID，也必须用导入行身份进入 MatchDecision / ManualOverride。
- 批次存在成功和失败条目时状态为 `PARTIAL`，报告成功、失败和跳过数量。
- 数据层抛出稳定的领域错误码；原始 SQL、数据库 URL、上游 payload 和堆栈不得直接传到 UI。
- UI Query Service 对无数据、未找到和暂时不可用使用明确结果/受控错误，不显示数据层内部错误文本。

### 7.4 RYM 评分快照与分类

```ts
interface RymRatingSnapshot {
  id: string;
  albumId: AlbumId;
  importRunId: ImportRunId;
  sourceRowKey: string;
  rating: number | null;
  ratingCount: number | null;
  primaryGenres: readonly TaxonomyObservation[];
  secondaryGenres: readonly TaxonomyObservation[];
  descriptors: readonly TaxonomyObservation[];
  observedAt: string | null;
  importedAt: string;
  normalizedContentHash: string;
  isPublished: boolean;
}

interface TaxonomyObservation {
  termId: string;
  sourceValueAtObservation: string;
  position: number;
}
```

规则：

- rating 与 ratingCount 同属一个快照。
- `null` 表示来源缺失；0 只有来源明确提供合法 0 时才保留。
- 三类 taxonomy 分别存储，不能合并成无类型标签表。
- 每类按 `position` 保留输入顺序。
- 每条 observation 通过 `termId` 引用 TaxonomyTerm；`sourceValueAtObservation` 保留本次离线快照中的原始显示文本，不能只保存无法关联的裸字符串。
- 未知来源值先创建未发布的待审查 TaxonomyTerm，不得静默映射到相似但错误的既有 term；对应 RatingSnapshot 在分类决策完成前不得发布。
- 页面默认读取最近一条已发布快照，不读取尚未通过冲突检查的导入。
- `normalizedContentHash` 相同且观察时间未变化时，幂等导入不新增重复快照。
- 评分使用精确十进制语义，不以二进制浮点作为数据库权威存储；允许范围和小数位在真实离线样本确认后冻结。
- read model 只有在 score 与 ratingCount 都合法存在时输出完整 `RymRatingView`；不完整快照仍保留审计，但不参与首页高分和评分排序。
- v0.2 的 `2500` 仅是 Mock 首页演示门槛，不写入 Repository、schema、RatingSnapshot 或生产默认配置。
- `albumId` 是评分快照的 canonical 主体引用，不是 RYM 外部身份映射。
- 没有稳定 RYM opaque ID 或规范化 URL 时，不创建 ExternalIdentifier；`(importRunId, sourceRowKey)` 唯一定位导入行，并派生无冲突的 `sourceReferenceKey` 进入 MatchDecision / ManualOverride。
- 未匹配行不得发布 RymRatingSnapshot。当前快照契约要求 `albumId`，因此匹配完成前只保留导入行、匹配决策和冲突状态；匹配完成后才可创建快照，并在 taxonomy 与发布检查通过后标记为已发布。
- 匹配完成后的 `RymRatingSnapshot.albumId` 只表示快照主体；匹配历史继续由 MatchDecision / ManualOverride 审计。
- RYM 若存在稳定 opaque ID 或规范化 URL，匹配成功后可以创建 ExternalIdentifier；它仍是该稳定外部身份关联 canonical entity 的唯一权威。

### 7.5 匹配与人工覆盖

```ts
type MatchDecisionStatus =
  | "AUTO_MATCHED"
  | "NEEDS_REVIEW"
  | "MANUALLY_MATCHED"
  | "REJECTED";

interface MatchDecision {
  id: string;
  source: SourceSystem;
  sourceReferenceKey: string;
  externalIdentifierId: ExternalIdentifierId | null;
  candidateAlbumId: AlbumId | null;
  status: MatchDecisionStatus;
  strategyVersion: string;

  decidedAt: string;
  supersedesDecisionId: string | null;
}

  id: string;
  source: SourceSystem;
  sourceReferenceKey: string;
  externalIdentifierId: ExternalIdentifierId | null;

  createdAt: string;

```

规则：

- 自动重试追加新 MatchDecision，不覆盖历史。
- `sourceReferenceKey` 只定位导入行或运行条目，不能替代 ExternalIdentifier；存在稳定外部身份时必须同时引用 externalIdentifierId。
- 对没有稳定 RYM 外部 ID 的行，`sourceReferenceKey` 必须由 `(importRunId, sourceRowKey)` 确定性生成或等价地保持同一唯一范围；不得伪造 ExternalIdentifier。
- 匹配完成前不得发布 RymRatingSnapshot；匹配完成后快照的 albumId 只是 observation subject reference，决策与人工覆盖历史仍保留。
- 有效 ManualOverride 优先于自动匹配。
- 人工拒绝必须阻止同一策略版本重复自动绑定。
- 0.15A 的失败搜索样本证明匹配失败应可报告、可重试，不能强行绑定。

## 8. 幂等与冲突规则

### 8.1 网易云目录

1. 只通过 ExternalIdentifier 的 `(NETEASE, entityType, externalId)` 定位来源身份和 canonical entity。
2. SourceRecord 通过 `externalIdentifierId` 定位来源身份，不保存第二份 canonical 映射。
3. 无稳定 externalId 的条目不创建 ExternalIdentifier、SourceRecord 或 canonical entity，只追加 RunEntryFailure。
4. 同一规范化 payload hash 的重复抓取不重复创建 canonical entity 或相同观察快照。
5. 新 payload 创建观察快照，并按字段所有权规则更新 canonical 投影。
6. 标题、日期、曲目数量或艺术家出现冲突时保留新旧 SourceFetchSnapshot。
7. `reconcileAlbumTracks` 按 track ExternalIdentifier 对齐并返回五类计数；缺失可靠 ID的候选计入 unresolved，未出现旧曲目计入 wouldDelete，但 v0.3 不自动删除。
8. 来源中缺失字段不自动删除已有已确认值；destructive delete 需要真实来源语义和独立策略。

### 8.2 新发行发现

1. 频道成员关系使用稳定唯一键 upsert。
2. 同一专辑多个频道分别保留。
3. 单次列表未出现某张专辑不等于删除；需要连续观察策略后才允许失效，策略在真实分页验证后确定。
4. ALL 读模型按 AlbumId 去重，并保留 `sourceMarketChannels` 集合。

### 8.3 RYM 导入

1. `(fileChecksum, normalizerVersion)` 标识同一规范化输入。
2. `(importRunId, sourceRowKey)` 在单次导入内唯一定位 RYM 行，并作为 `sourceReferenceKey` 的确定性来源；没有稳定外部 ID 时不创建 ExternalIdentifier。
3. 重复 dry-run 不写入 canonical 或发布快照。
4. 同一输入重复 import 返回已有结果，不复制快照。
5. rating、ratingCount 和 taxonomy 作为一个原子快照发布。
6. 未匹配、低置信或多候选行进入冲突报告，不自动创建假专辑，也不发布 RymRatingSnapshot。
7. ManualOverride 变更后重新执行匹配，保留旧决策链；匹配完成并通过发布检查后，快照的 `albumId` 只作为 observation subject reference。

## 9. 字段所有权与合并优先级

| 字段 | 主来源 | 合并规则 |
| --- | --- | --- |
| 专辑外部 ID、标题、别名、艺术家、发行日期、类型、公司、封面、曲目 | 网易云目录同步层 | canonical 使用最近有效、已发布的网易云观察；保留历史快照 |
| RYM rating、ratingCount | RYM 离线导入层 | 只从同一条已发布 RatingSnapshot 读取 |
| Primary Genres、Secondary Genres、Descriptors | RYM 离线导入层 | 从同一已发布快照读取，保持类别和顺序 |
| slug | 本地系统 | 根据 canonical 标题生成并保留历史 |
| 市场频道、来源 endpoint、first/last discoveredAt | 网易云新发行来源上下文 | 只存在于 NewReleaseDiscovery；读模型取匹配 memberships 的最小/最大值 |
| createdAt、updatedAt | 本地系统 | 不从上游覆盖 |

网易云和 RYM 对同一字段都提供值时，不进行无规则覆盖。字段所有权表之外的输入进入来源记录或冲突报告，等待产品决策。

### 12.3 CatalogWriteService 与事务边界

```ts
interface CatalogUnitOfWork {
  runInTransaction<T>(
    operation: (repositories: {
      canonical: CanonicalCatalogRepository;
      observations: SourceObservationRepository;
    }) => Promise<T>,
  ): Promise<T>;
}

interface CatalogWriteService {
  persistCatalogObservation(input: CatalogObservationWrite): Promise<AlbumId>;
  publishRymRatingSnapshot(input: RymSnapshotPublicationWrite): Promise<string>;
  recordNewReleaseDiscovery(input: NewReleaseDiscoveryWrite): Promise<string>;
}
```

CatalogWriteService 是 Provider/导入流程调用的高层边界，并使用 CatalogUnitOfWork 原子组合两个 Repository：

- canonical album、ExternalIdentifier、SourceRecord 和 SourceFetchSnapshot 同一专辑事务成功或回滚。
- album、artists、credits、aliases、tracks、company、cover 和 slug 保持单张专辑一致写入。
- rating、ratingCount、三类 taxonomy observations 和发布状态在同一快照事务成功或回滚。
- RYM 快照发布前必须存在可审计的匹配结果；快照 albumId 是 observation subject reference，匹配决策链不得被快照替代。
- NewReleaseDiscovery 必须引用已存在 Album 和真实 SyncRun；失败不留下半条 membership。
- RunEntryFailure 可在失败事务之外写入运行级审计，不能因专辑事务回滚而丢失失败事实。

内存 UnitOfWork 使用 copy-on-write state 并只在成功后替换；Prisma UnitOfWork 使用数据库事务。页面不得调用上述写入边界。

### 12.5 稳定排序

所有排序最终都以 `album.id ASC` 作最后 tie-break，确保内存和数据库结果一致。v0.3 冻结以下算法。

#### PartialDate tuple

已知日期先转换为比较 tuple，不生成虚假 canonical 日期：

- `YEAR`：`[year, 0, 0, 1]`
- `MONTH`：`[year, month, 0, 2]`
- `DAY`：`[year, month, day, 3]`
- `UNKNOWN`：不生成数值 tuple，始终排在所有已知日期之后。

升序和降序都使用同一 tuple 的字典序，只反转已知 tuple 的比较方向；UNKNOWN 在两个方向都保持最后。日期相同后使用统一标题 comparator，再使用 AlbumId。YEAR 不写成 1 月 1 日，MONTH 不写成该月 1 日。

#### Seeded random

每张候选专辑计算 UTF-8 字节串 `seed + "\0" + albumId` 的 SHA-256。按 32 字节 hash 从左到右无符号升序，hash 相同时按 AlbumId 升序。memory 与 database 后端必须由同一 Query Service TypeScript helper 执行该算法并获得同一顺序。

v0.3 合成 fixture 数据量允许 Query Service 对有界候选集执行 hash 排序；这不构成真实规模分页或生产随机查询的可扩展性证明。进入真实规模数据前必须另行验证抽样和索引方案。

#### 标题比较

v0.3 保持当前 `title.localeCompare(otherTitle, "zh-CN")` 产品语义，并集中为一个 TypeScript comparator。Node Intl 与 PostgreSQL collation 不保证完全一致，因此数据库不得先用另一套 locale 排序后声称与 memory 一致；合成 fixture 阶段的最终标题 tie-break 由 Query Service 的同一 comparator 执行，再按 AlbumId。

v0.3 合成契约验证必须先取得有界候选集、运行统一 TypeScript comparator，再切分 Page；不能先按不同数据库 collation 分页。进入真实规模数据前必须重新验证 PostgreSQL 原生 collation、索引、游标分页和中文部分搜索。未通过该验证前，不得宣称当前排序或搜索可扩展到生产数据量。

搜索顺序保持 v0.2 契约：

1. 标题精确匹配。
2. 别名精确匹配。
3. 艺术家精确匹配。
4. 标题部分匹配。
5. 别名部分匹配。
6. 艺术家部分匹配。
7. 同一优先级按发行日期降序。
8. 再按上述统一 `zh-CN` 标题 comparator 稳定排序。
9. 最后按 AlbumId 排序。

同一专辑同时命中多个字段时只返回一次，`matchReason` 使用最高优先级命中。

发现页和新发行页沿用当前 URL 稳定值；中文显示名继续由 `getDisplayLabel` 产生，不替换内部值。

- 保留 v0.2 页面和测试。

## 14. 数据库技术建议

### 14.1 方案比较

| 维度 | Prisma + SQLite | Prisma + PostgreSQL | 开发 SQLite／生产 PostgreSQL | 不用 Prisma：Drizzle/Kysely/原生 SQL |
| --- | --- | --- | --- | --- |
| Windows 本地成本 | 最低，文件数据库 | 需要本地服务或获准容器 | 本地低、生产另配 | 取决于所选数据库，仍建议 PostgreSQL |
| 生产部署 | 适合单实例轻量场景；并发写受限 | 托管选择成熟，适合后续同步 | 生产可用，但本地不能证明同一语义 | 可用，迁移和类型边界需自行建立 |
| JSON／raw payload 引用 | JSON 能力有限；原始 payload 仍应外置 | JSONB 与索引较成熟；原始 payload 仍外置 | JSON、排序和函数存在差异 | PostgreSQL 能力可完整使用 |
| 中文部分搜索 | 当前小数据可用；长期能力有限 | 可先保持 substring，后续独立评估索引 | 本地/生产查询计划与排序可能漂移 | 控制力高，但实现成本更高 |
| 并发同步与批处理 | 写锁限制明显 | 事务、并发 upsert 和批处理更合适 | 本地无法覆盖生产并发 | PostgreSQL 下可行，需更多手写事务 |
| migration 一致性 | 单 Provider 简单 | 单 Provider 一致 | 双 Provider 最易漂移 | 取决于 migration 工具和纪律 |
| 测试隔离 | 临时文件方便 | 独立 test database/schema，成本较高但贴近生产 | 测试不覆盖生产 Provider | 可用事务/schema隔离，工具需自建 |
| 日期、枚举、约束 | check 可用但类型能力较弱 | date/timestamptz、check、索引明确 | Provider 映射存在差异 | 原生 PostgreSQL 最强，类型层需维护 |
| 未来数据量 | 小中型单机 | 适合目录、曲目、快照持续增长 | 生产适合，但开发证据不等价 | 与 PostgreSQL 相同，工程成本较高 |
| Next.js build/runtime | 文件访问在 server runtime；部署限制明显 | server runtime 连接池需显式管理 | 两套 runtime 风险 | 需自行处理 client 生命周期与 bundle 边界 |
| 类型与开发体验 | Prisma 类型化较好 | Prisma 类型化和 migration 边界较好 | 表面统一，Provider 差异仍存在 | Drizzle 类型化；Kysely/SQL 控制强，样板更多 |

推荐依据：项目需要有序关系、唯一约束、来源快照、并发幂等和后续批处理，且内存 Repository 已承担低成本本地 UI 开发。因此推荐单一 PostgreSQL Provider，减少开发/生产语义漂移。

### 14.2 推荐

v0.3D 推荐使用 PostgreSQL + Prisma，理由：

- 专辑、艺术家、曲目、credit、外部 ID、来源快照和 taxonomy 是关系结构。
- 有序多对多、唯一约束、事务 upsert 和历史快照需要可靠关系数据库。
- PostgreSQL 能支持后续搜索、JSON 元数据、并发同步和约束。
- Prisma 为当前 TypeScript/Next.js 工程提供类型化 schema 和 migration 边界。

这是一项待 0.3D 人工批准的实现决定，本阶段不安装依赖、不创建 schema。

0.3P、0.3A、0.3B 和 0.3C 均不得安装 Prisma 或创建数据库。0.3D 开始前必须重新批准本地、CI、部署、备份和连接池方式，并核对届时官方兼容性；无 PostgreSQL 环境时停止。Prisma 无法满足关键事务或约束时重新比较备选，不同时安装两个 ORM。

### 14.3 不推荐方案与备选

不采用“开发 SQLite、生产 PostgreSQL”的默认方案，原因：

- schema、migration、排序规则、日期、JSON 和全文搜索行为可能漂移。
- 无法用本地测试充分证明生产 PostgreSQL 语义。
- 当前内存 Repository 已承担无数据库的快速开发用途。

SQLite 只在项目被明确改为单机、本地、单进程且不需要并发同步时作为独立架构决策重新评估，不能与 PostgreSQL schema 静默混用。

Prisma + SQLite 不作为当前推荐，因为它不能代表目标并发同步和 PostgreSQL约束。Drizzle/Kysely/原生 SQL 是 Prisma 无法满足关键事务、索引或部署条件时的备选，不与 Prisma 同时引入。

### 14.4 尚未解决与改选条件

出现以下任一情况时，0.3D 停止并重新比较 Prisma、Drizzle/Kysely 和原生 SQL：

- 目标部署环境不能提供 PostgreSQL。
- 当前获准 Prisma 版本不支持项目 Node.js / Next.js 运行环境。
- 关键事务、批量 upsert、索引或搜索必须依赖大量不可维护的 raw SQL。
- 迁移流程无法在 CI 与本地测试中重复执行。
- 目标 PostgreSQL 的运行、备份和连接池方式尚未获得批准。
- 中文搜索的数据量、查询计划和索引尚未用真实规模数据验证；v0.3 保持现有部分匹配语义，不提前引入搜索引擎。

不得在没有真实阻塞证据时同时引入两个 ORM。

## 15. 错误模型

```ts
type CatalogErrorCode =
  | "VALIDATION_FAILED"
  | "SOURCE_UNAVAILABLE"
  | "SOURCE_RATE_LIMITED"
  | "NORMALIZATION_FAILED"
  | "MATCH_REQUIRED"
  | "CONFLICT"
  | "NOT_FOUND"
  | "PERSISTENCE_FAILED";

interface CatalogError {
  code: CatalogErrorCode;
  operation: string;
  retryable: boolean;
  publicMessage: string;
  internalCauseReference: string | null;
}
```

规则：

- parser 返回字段级 validation issue；批处理汇总为稳定错误码。
- 403、429、验证码或平台限制映射为不可自动重试或需人工判断的来源错误，不能循环重试。
- 单条失败默认不回滚同批已验证条目；原子 RatingSnapshot 和单张专辑事务失败时回滚该事务。
- `publicMessage` 不包含 SQL、堆栈、payload、文件绝对路径或凭据。
- `internalCauseReference` 指向受控日志事件，不把异常对象持久化到页面 read model。
- Query Service 的 NOT_FOUND 返回 null；系统不可用错误由页面边界转换为统一错误状态，不能伪装为空结果。

## 16. 版本化

必须分别记录：

- `parserVersion`：unknown payload 到来源 DTO 的规则版本。
- `normalizerVersion`：来源 DTO 到标准化输入的规则版本。
- `mappingVersion`：raw album type、taxonomy 等到内部枚举/键的映射版本。
- `matchStrategyVersion`：来源记录匹配 canonical entity 的策略版本。
- `schemaMigrationVersion`：数据库 migration 历史。
- `readModelVersion`：只有跨进程发布快照时记录；进程内 TypeScript 投影不额外持久化。

版本变化不能原地改写历史快照。需要重放时创建新运行和新观察，保留旧 hash、版本与决策链。前台只读取明确发布的当前投影。

## 17. Schema 级约束摘要

后续数据库 schema 至少需要：

- Album、Artist、Track 使用内部主键。
- 当前 slug 唯一，slug 历史一对一映射到 Album。
- ExternalIdentifier 的来源、实体类型、外部 ID 联合唯一。
- ExternalIdentifier 恰好一个 canonical 外键非空且与 entityType 一致；它是来源身份关联的唯一权威。
- SourceRecord 必须引用 ExternalIdentifier；不得包含 canonicalEntityId，`(externalIdentifierId, endpoint, contextHash)` 唯一。
- AlbumAlias、ArtistAlias 和 ReleaseCompanyCredit 在 0.3D schema 中没有 `sourceRecordId` 列；0.3E 才通过 migration 增加 nullable、已索引且 `ON DELETE SET NULL` 的 provenance 外键。
- NewReleaseDiscovery.albumId 与 RymRatingSnapshot.albumId 是 observation subject reference；Observation / Snapshot 不得另存可独立解析的 `source + entityType + externalId + canonicalEntityId` 身份映射。
- RunEntryFailure 的 syncRunId 与 importRunId 恰好一个非空；没有稳定 externalId 的失败不得引用虚假 SourceRecord。
- AlbumArtistCredit 的 `(albumId, position)` 唯一。
- Track 的 `(albumId, position)` 唯一。
- TrackArtistCredit 的 `(trackId, position)` 唯一。
- ReleaseCompanyCredit 的 `(albumId, position)` 唯一。
- NewReleaseDiscovery 的来源、专辑、频道、endpoint 联合唯一。
- RYM 导入行的 `(importRunId, sourceRowKey)` 唯一；未匹配行不得发布 RymRatingSnapshot，也不得创建虚假 ExternalIdentifier。
- TaxonomyTerm 的 `(source, kind, stableKey)` 唯一。
- RatingSnapshot taxonomy 的 `(snapshotId, category, position)` 唯一，且每条 observation 必须引用 termId 并保存 sourceValueAtObservation。
- 非负 duration、ratingCount 和位置检查。
- PartialDate precision 与 year/month/day 一致性检查。
- rating 与 ratingCount 都可空，不以 0 代替缺失。
- 级联删除策略显式定义；来源审计记录默认不得随 canonical 删除而静默消失。
- PrototypeFixtureState 及其三类 fixture 结构不进入生产 schema。

Prisma 无法表达的数据库 check constraint 必须在 migration SQL 中声明，并由集成测试验证。

## 18. 安全与发布边界

- 前台永不实时请求网易云或 RYM。
- Provider 获取与导入只在明确授权的离线流程运行。
- 不保存 Cookie、Token、Authorization、Set-Cookie、浏览器数据、账号信息或设备标识。
- 原始来源载荷若需保留，必须进入受控、非公开、非 Git 存储，并以引用和 hash 关联。
- 发布 read model 只读取通过校验、匹配和发布门的快照。
- RYM 导入器记录来源说明和导入时间；是否允许发布由独立政策门决定。
- 市场频道不能被映射为国家、地区、语言、国籍或法域。
- 缺失字段隐藏或显示明确不可用状态，不猜测。

- 把 v0.2 CSS 封面、虚构评分或虚构曲目作为生产 seed。

- 拼音搜索、全文搜索引擎或 AI 匹配。

- 未经独立授权的依赖安装、数据库服务、部署和真实数据访问。
