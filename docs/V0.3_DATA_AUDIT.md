### 3.4 当前 Mock 的重复字段与拆分要求

| 当前字段或结构 | v0.3 处理方向 | 原因 |
| --- | --- | --- |
| `releaseYear` | 从结构化发行日期派生，不重复持久化为权威值 | 避免日期更新后不一致 |
| `artists: string[]` | 拆为 Artist、AlbumArtist、TrackArtist | 需要内部 ID、外部 ID、顺序和 credit |
| `company: string` | 拆为有序发行公司 credit | 来源可能为空、单个或多个 |
| 三类 RYM 数组 | 放入带快照和来源的 RYM 观察记录 | 分类会随导入批次变化，不是网易云固有字段 |
| `rymScore` / `rymRatingCount` | 同一评分快照中的可空字段 | 两者必须共享观察时间和来源批次 |
| `cover` | 保留为测试 fixture；生产模型改用 CoverAsset | CSS 图形不能迁移为真实封面 |
| `addedAt` | 改为目录入库或来源发现时间 | 它不是专辑发行信息 |
| `neteaseUrl` | 由已确认的网易云专辑外部 ID生成或发布 | 避免手工、不一致 URL |
| Mock `id` | 仅 fixture 标识；正式内部 ID 与来源 ID 分离 | 避免 Provider 绑定 |

### 4.2 当前字段消费

- `AlbumCard` 消费 slug、封面、标题、艺术家、发行年、RYM 评分、前两个主流派。
- 首页近期发行依赖 `releaseDate`。
- 首页高分专辑依赖 `rymScore`、`rymRatingCount` 和 v0.2 Mock 专用门槛。
- 首页流派入口依赖当前主流派稳定值、`getDisplayLabel` 和 `primaryGenre` URL 契约。
- 发现页依赖 `releaseYear`、发行类型和三类 RYM 分类。
- 搜索依赖标题、别名、艺术家和发行日期；同一专辑最多返回一次。
- 新发行依赖来源上下文中的频道和专辑 ID，且需保留跨频道关系。
- 详情页依赖可空发行公司、评分快照、分类、曲目位置和时长。

### 4.3 当前数据访问问题

页面和纯函数直接 import `src/data/*.mock.ts`，因此当前缺少：

- 页面与存储之间的 Repository / Query Service 边界。
- 可替换的内存实现与数据库实现契约。
- 来源 DTO 与规范化领域对象之间的隔离。
- 分页契约。
- 持久化唯一约束和幂等规则。
- 来源观察时间、导入批次、匹配决策和人工覆盖记录。

这些问题不影响 v0.2 静态原型，但会阻止安全地切换到真实数据。

- 46 次网易云相关请求均获得 HTTP 成功响应。
- 实验未使用登录、Cookie、Token、Authorization、自定义规避请求头、代理或并发采集。
- 仅访问 `music.163.com`。
- 18 个清单样本中，17 个完成规范化。
- 唯一未规范化样本为 `A Star Is Born Soundtrack`；搜索 HTTP 成功，但本地候选选择没有达到实验的置信要求。
- 17 个详情样本共产生 208 条规范化曲目。

### 6.3 设计推论

- 网易云外部 ID 应以字符串保存，并通过独立 ExternalIdentifier 与内部 ID 关联。
- DTO 中所有非身份字段都应允许缺失或无效，并保留原始取值、映射版本和观察时间。
- 发行公司、别名、类型和子类型不能在 DTO 层强制为非空。
- 曲目必须保存显式碟序、曲序和稳定排列位置，不能按数组下标重新编号。
- 响应原文不应直接暴露给页面；规范化结果进入领域层前必须校验。

### 6.4 等待后续验证

- 分页、增量同步、删除或下架行为。
- 类型和子类型的完整取值集合。
- 不完整发行日期的实际表现。
- 封面 URL 生命周期、尺寸变体与缓存边界。
- 大规模请求稳定性、长期平台规则和生产使用边界。
- 重名、豪华版、重制版、多艺术家专辑的自动匹配准确度。

## 8. RYM 边界审计

### 8.1 已确认事实

- 仓库没有 RYM CSV、JSON 或其他真实离线数据文件。
- 仓库没有 RYM 导入实现，也没有 RYM 网络请求或抓取代码。
- 当前页面中的 RYM 评分、评分人数、Primary Genres、Secondary Genres 和 Descriptors 全部为虚构 Mock 数据。
- 项目决策要求 RYM 数据仅通过用户提供的离线文件导入。
- `rym-data-import` Skill 只负责本地校验、标准化、专辑匹配、dry-run、幂等导入和冲突报告。
- 导入记录必须包含数据来源说明与导入时间；Skill 不负责获取、登录、绕过访问限制，也不自行判断或证明用户提供文件的授权状态。

### 8.2 数据契约要求

- `rating` 与 `ratingCount` 必须属于同一个带时间的评分快照。
- 缺失评分是 `null`，不能转换为 0。
- Primary Genres、Secondary Genres 和 Descriptors 必须保持三类独立、有序集合。
- 每次导入必须保留文件校验和、规范化器版本、来源说明、导入时间和批次状态。
- RYM 分类和评分不能混入网易云来源 DTO。
- 自动匹配、人工确认、拒绝和人工覆盖必须可追踪。
- 页面只能消费已发布的本地快照，不能运行时依赖 RYM。

### 8.3 等待后续确认

- 离线文件的真实字段名、编码、分隔符和缺失值规则。
- 评分精度、评分人数范围和同一专辑多版本表示。
- Primary / Secondary / Descriptor 的顺序语义与重复项规则。
- 数据来源政策门是否允许某个批次发布。导入器记录来源，不替代独立的发布合规决策。

## 9. 缺失值与时间语义现状

当前 Mock 使用完整日期字符串和扁平空值，无法表达真实来源的差异。v0.3 需要区分：

- DTO 字段未出现。
- DTO 字段显式为空。
- DTO 字段格式无效。
- 规范化后字段合法但业务未知。
- 集合没有成员。

当前时间字段混合了不同语义：

- `releaseDate`：作品发行日期。
- `addedAt`：本地原型的收录时间。
- `discoveredAt`：通过某个新发行频道发现的时间。
- 实验中的 `fetched_at`：HTTP 获取时间。

这些时间不能复用同一字段。真实契约必须明确 `releaseDate`、`fetchedAt`、`observedAt`、`importedAt`、`discoveredAt`、`createdAt` 和 `updatedAt`。

当前 Mock 每条 membership 只有一个 `discoveredAt`。正式 NewReleaseDiscovery 需要聚合为 `firstDiscoveredAt` 与 `lastDiscoveredAt`；prototype adapter 直接建立 fixture membership，不伪造支撑该聚合的真实 SyncRun。

## 12. 审计结论

v0.2 已经验证了页面信息架构和本地交互契约，但其 Mock 类型不能直接升级为正式数据库模型。v0.3 应先建立四层边界：来源 DTO、规范化领域模型、带时间和来源的观察记录、页面只读模型；再通过内存 Repository 保持现有行为，最后在独立阶段引入 PostgreSQL 与 Prisma。

0.15A 支持“网易云继续作为专辑目录候选来源”的有限结论；0.15B 明确否定将网易云市场频道解释为地区字段。RYM 仍只有离线导入边界，没有真实输入结构。任何数据库或 Provider 实现都必须等待本审计、数据契约和执行计划获得人工批准。
