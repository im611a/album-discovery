# 路线图

路线图使用显式阶段门。完成一个阶段不会自动授权下一个阶段，版本边界也可以根据真实
数据源验证结果调整。

## 0.1 工程与决策基线（已完成）

- Next.js、TypeScript、Tailwind CSS、ESLint、Vitest 与 Git 基础工程；
- 项目级 Skills、产品与数据文档；
- shadcn/ui 最小基础配置；
- lint、typecheck、test 和 build 质量门。

## 0.15 网易云可行性验证（已完成）

0.15A 验证匿名核心目录字段，0.15B 验证地区与市场分类信号。结论是核心专辑元数据具备
小规模匿名可行性，但地区和语种字段不可用；`ZH`、`EA`、`JP`、`KR` 只能作为新发行
请求侧市场频道。实验不证明生产、全量或长期稳定性。

## 0.16 正式产品方案收敛（已完成）

- 使用统一专辑目录，取消国内／国外一级分区；
- 主导航收敛为首页、发现专辑和新发行，搜索作为独立入口；
- 网易云市场频道只用于新发行来源上下文；
- 核心模型不强制国家、地区、国籍或语言字段；
- 正式文档和数据来源边界完成同步。

## v0.2 静态产品原型（已完成）

已完成：

- 首页：近期发行、高分专辑、按流派探索、随机发现；
- 发现专辑：筛选、排序、URL 恢复、清除与空状态；
- 新发行：五个市场频道、发行类型、去重、日期排序和 URL 恢复；
- 搜索：标题、别名和艺术家匹配、六级优先级、URL 与 history；
- 专辑详情：禁用网易云入口、分类、评分、曲目和来源说明；
- 友好 404 与 18 个静态详情路由；
- 360px、768px、1280px 响应式与键盘可访问性验收；
- 19 个测试文件、167 个测试用例和 25 个静态页面构建输出；
- 全程只使用完全虚构的本地 Mock 数据。

v0.2 产品实现、自动验证、人工验收和最终文档均已完成。是否已经 fast-forward 到 main
以当前 Git 历史为准。项目仍未部署，未接入网易云或 RYM，未创建数据库，也未实现正式
Provider。

## v0.3 数据契约与正式数据库基础（未开始）

目标是先冻结正式数据边界，再决定持久化实现。执行顺序：

1. 回读网易云实验结构与已保存的匿名响应形状；
2. 定义网易云和 RYM 来源 DTO；
3. 定义标准化专辑、艺术家、曲目、评分与分类模型；
4. 定义 Repository 契约和页面需要的读模型；
5. 定义字段缺失、来源追踪、批次与发布时间策略；
6. 完成上述审计后再设计 Prisma Schema 和迁移；
7. 将页面数据读取从 Mock 迁移到 Repository。

当前 Mock 类型不是数据库模型。路线图不预先确定表、关系或迁移结果，也不授权安装
Prisma、接入 PostgreSQL 或导入真实数据。

## v0.4 网易云 Catalog Provider 与同步适配层（未开始）

在独立授权和平台边界复核后，实现网易云目录 DTO 映射、批次同步、增量策略、失败处理、
来源追踪和发布读模型。前台仍不得实时请求网易云。

## v0.5 RYM 离线导入与匹配（未开始）

只处理用户明确提供的离线文件：校验、标准化、专辑匹配、dry-run、幂等导入、冲突报告
与人工覆盖。该阶段不负责抓取、登录或绕过 RYM 访问限制。

## v0.6 真实数据联调与发布准备（未开始）

- 网易云与 RYM 真实数据联调；
- 性能、SEO、可访问性和数据新鲜度；
- 部署、监控、回滚和长期更新策略；
- 合规与平台规则复核。

是否部署仍需独立明确授权。

## 当前停止点

v0.2 已完成。合并 main、创建 tag、开始 v0.3 和访问真实数据源仍分别需要独立人工授权；
完成 v0.2 不自动授权 v0.3。
