# Open-source reference audit

## 何时触发

- 需要评估一个或多个公开仓库能否作为架构、交互或工程实践参考时。
- 需要核对仓库是否归档、许可证、近期维护、认证依赖或已知风险时。
- 需要更新 `docs/OPEN_SOURCE_REFERENCES.md` 时。

## 何时不触发

- 不用于实现网易云目录同步；那属于 `netease-catalog-ingestion`。
- 不用于导入 RYM 数据；那属于 `rym-data-import`。
- 不用于页面或组件开发；那属于 `minimal-album-ui`。
- 不用于执行仓库质量检查；那属于 `quality-gate`。

## 执行步骤

1. 明确研究问题、目标仓库和审计日期。
2. 优先读取仓库元数据、README、LICENSE、发布记录和官方文档等一手资料。
3. 记录用途、归档状态、许可证、维护迹象、工作原理、认证依赖和风险。
4. 将每条结论标记为“已确认事实”“推测”或“等待后续验证”。
5. 提炼可借鉴的模式，并明确不复制、不直接集成或需要法律复核的部分。
6. 把带来源链接的结论写入指定文档，注明信息截止日期。

## 安全边界

- 只读研究；不得 clone 后运行安装、构建、测试或启动脚本。
- 不调用被研究项目所连接的第三方服务，也不提交账号、Cookie 或令牌。
- 不把 stars、活跃提交或许可证当作接口合法性、可用性或稳定性的保证。
- 未经明确授权，不下载大体积资产、不复制源码、不修改外部仓库。

## 输出要求

- 每个仓库至少包含：用途、归档状态、许可证、维护状态、工作原理、接口或能力、登录依赖、稳定性风险和不直接集成的原因。
- 必须附一手来源链接和审计日期。
- 必须单列事实、推测和待验证事项，禁止把阅读代码所得推断写成实测结论。
