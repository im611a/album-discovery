# Quality gate

## 何时触发

- 一个阶段、功能或修复即将交付时。
- 用户明确要求运行 lint、typecheck、test、build 或检查 Git 状态时。
- 需要确认禁用功能或禁用数据源没有被误写为正式方案时。

## 何时不触发

- 不用于设计产品、实现采集、导入 RYM、研究开源项目或开发 UI。
- 不在只要求解释而未要求执行命令的场景擅自运行耗时检查。

## 执行步骤

1. 读取 `AGENTS.md`、当前阶段范围和 `package.json` 中的实际脚本。
2. 检查变更文件，确认没有越过授权范围或混入凭据、缓存和生成物。
3. 搜索阶段指定的敏感关键词，逐条判断是禁用说明还是误实现。
4. 依次运行 `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build`。
5. 对失败保留原始命令和核心错误；只有任务允许修复时才做最小修复并复跑。
6. 运行 Git 状态检查，确认分支、跟踪状态和是否存在意外文件。

## 安全边界

- 不提交、不推送、不部署，也不自动进入下一阶段。
- 不为让检查通过而关闭规则、删除测试、放宽类型或忽略失败。
- 不安装无关依赖，不发起产品数据源请求，不读取仓库外的私密文件。
- 构建生成物必须保持在忽略目录内。

## 输出要求

- 对每条命令报告实际通过/失败、测试数量和构建摘要，不得只写“正常”。
- 列出范围审计和关键词审计结果、遗留风险与当前 Git 状态。
- 明确说明是否产生提交、部署或外部数据请求。
